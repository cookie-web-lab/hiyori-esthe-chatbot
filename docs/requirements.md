# エステサロン問い合わせ対応チャットボット 要件定義

2026-11-14 作成

## 概要・目的

架空のフェイシャルエステサロン「private esthe salon hiyori」の問い合わせに24時間答えるチャットボットを、Difyで費用0円で作る。

- **目的**:Webデザイナーとしてのポートフォリオにする。「HPにこんなボットも付けられます」と見込み客に見せられる実物サンプルにする
- **背景**:個人で営業するエステサロンは施術中にDMや電話に出られず、初めての人は予約前の不安(痛み・勧誘・料金)が多い
- **ゴール**:単なるFAQではなく、①予約前の不安を解消し、②お悩みに合うメニューを提案し、③予約ページへつなげるボットとして公開する

## 想定ユーザーと利用シーン

メインの利用者は、初めてサロンを利用するか迷っている女性。

| 利用者 | 利用シーン | 知りたいこと |
| --- | --- | --- |
| 初めての方(20〜40代の女性) | インスタからHPを見に来て、夜や昼間にスマホで質問する | 初回料金、痛み、勧誘の有無、敏感肌でも大丈夫か |
| リピーター | 予約前に細かいことを確認する | オプション料金、回数券、キャンセル規定 |
| 見込み客(サロンオーナー) | ポートフォリオとして見せられる | 自分のお店に付けたらどうなるか |

## 機能要件

| No | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| 1 | よくある質問への回答 | ナレッジ(esthe_faq.md)をもとに、料金・施術内容・予約などに答える | 必須 |
| 2 | 予約前の不安解消 | 料金・勧誘・痛み・施術内容の質問に、安心できる一言を添えて答える | 必須 |
| 3 | お悩み別のメニュー提案 | お悩みを1〜2個聞き、ナレッジの「お悩み別おすすめメニュー」をもとに1つ提案する | 必須 |
| 4 | 予約への誘導 | 提案や回答の最後に、予約ページ・LINEのURLを案内する。空き状況は予約ページで確認してもらう | 必須 |
| 5 | カテゴリボタン | 6つのカテゴリをボタンで表示し、押されたらそのカテゴリを短く紹介し、フォローアップ機能で次の質問を3つボタン表示する(番号入力では検索できないため) | 必須 |
| 6 | 答えられない質問の案内 | ナレッジにない質問は推測せず、決まった文でLINEへ案内する | 必須 |
| 7 | 関係のない質問への対応 | サロンと関係のない質問には、サロンに関する質問をお願いする | 必須 |
| 8 | 回答の評価 | 公開画面の👍👎で、悪い回答をログで見つけやすくする | あれば良い |
| 9 | HPへの埋め込み | 架空サロンのHPにチャットボタンとして設置する | あれば良い(後日) |

## 回答ルール・表現ルール

効果を言い切らないことを最優先にし、このルールをDifyの指示文(プロンプト)に入れる。

**話し方**

- やわらかく丁寧な敬語で、短くわかりやすく答える
- 結論から答え、挨拶や共感の前置きは書かない
- 料金を答えるときは金額のあとに「(税込)」と添える

**表現のルール(薬機法・景品表示法への配慮)**

- 「必ず」「絶対」「〇回で治る」「シミが消える」「若返る」など、効果を言い切る表現は使わない
- 効果を聞かれたら「感じ方には個人差があります」と伝え、カウンセリングを案内する
- 肌の病気や症状の診断はしない。肌トラブルが心配な方には皮膚科への相談をすすめる

**答えられないとき**

- ナレッジにないことは推測しない。関係する情報が一部あれば、わかる範囲を答えてからLINEを案内する。まったく情報がない場合は「申し訳ありません、その件はLINEからお気軽にお問い合わせください」と決まった文で答える(ログで探しやすくするため)
- 空き状況はわからないため、予約ページでの確認を案内する

**メニュー提案の流れ**

1. お悩みや目的を聞く(例:「どんなお肌のお悩みがありますか?」)。1回に聞くのは1つだけ
2. 必要なら、肌質や初めてかどうかをもう1つだけ聞く
3. ナレッジの「お悩み別おすすめメニュー」をもとにメニューを1つ提案し、料金と時間を添える
4. 「最終的にはカウンセリングでお肌を見てご提案します」と伝える
5. 予約ページとLINEのURLを案内する

**カテゴリボタンが押されたとき**

- カテゴリ名(例:「料金・支払い」)だけが送られてきたら、そのカテゴリの内容を2〜3文で紹介し、下に出る質問ボタン(フォローアップ)から選んでもらう

## 会話・画面設計

開いた瞬間に「何を聞けばいいか」がわかる画面にする。

- **ボット名**:エステhiyori お問い合わせチャット
- **開始メッセージ**:「こんにちは。ご来店を検討いただきありがとうございます!気になることをお気軽にご質問ください。知りたい内容を選んでください。」
- **カテゴリボタン(Difyの開始時の質問で6つ表示)**:
    - 料金・支払い
    - お悩み別おすすめメニュー(「効果」は約束に見えるため使わない)
    - 施術内容
    - 痛み・肌への影響
    - 予約・アクセス
    - 初めてのご来店
- **ボタンを押した後**:カテゴリを短く紹介し、質問ボタンを3つ表示 → タップした質問に回答 → 予約ページを案内
- **アイコン・色**:サロンの雰囲気に合わせて、やわらかいベージュやピンク系(公開設定で変更)

## 技術構成・費用

すべて無料枠で作り、費用は0円。

| 項目 | 使うもの | 設定・メモ |
| --- | --- | --- |
| 開発環境 | Dify Cloud(Sandboxプラン・無料) | アプリは5個まで。付属の200クレジットは使わない |
| AIモデル | Gemini API(Google AI Studioの無料キー) | Flash-Liteを使う(1日の無料回数が多い)。上限はAI Studioで確認 |
| アプリの種類 | チャットボット | ワークフローは使わず、シンプルに作る |
| ナレッジ | esthe_faq.md(約40項目、カテゴリ名つき) | インデックス方式は「高品質」(Geminiの無料の埋め込みモデル gemini-embedding-001)。お客様は同じ言葉を使うとは限らないため、言い換えに強い方式を選んだ。検索はベクトル検索、Rerankは使わない |
| 公開 | DifyのWebアプリURL | 後日、HPに埋め込みコードで設置 |

注意:Geminiの無料枠は、入力内容がGoogleのサービス改善に使われる可能性がある。架空のお店なので問題ないが、本物のお客さんの個人情報は入れない。

## 対象外(今回やらないこと)

難しくしすぎないため、次のものは今回は作らない。

- 予約の受付や空き状況の確認(予約システムとの連携)
- LINE公式アカウントとの連携
- 写真を送ってもらって肌を判断する機能
- 英語など多言語への対応
- 有料モデル(OpenAIなど)の利用

## テスト計画と合格基準

公開前にプレビュー画面で20問ほど試し、すべての分類で合格基準を満たしたら公開する。

| 分類 | 質問例 | 合格基準 |
| --- | --- | --- |
| 基本の質問 | 初回体験はいくらですか? / 入会金はかかりますか? | ナレッジどおりに答える(初回5,500円、入会金なし) |
| 言い換えた質問 | 友達と行ってもいい? / すっぴんで行っていい? | 意味をとらえて正しく答える(ペアで順番に施術) |
| 不安系の質問 | 肌が弱いんですけど大丈夫? / 勧誘されますか? | 安心できる一言を添えて答える |
| メニュー提案 | 毛穴が気になるんですが、どれがいいですか? | 1つ質問を返すか、毛穴ケアフェイシャルを提案し、予約ページを案内する |
| カテゴリボタン | 「料金・支払い」ボタンを押す | そのカテゴリを短く紹介し、質問ボタンが表示される |
| 表現ルール | シミって消えますか? / 1回で変わりますか? | 効果を言い切らず、個人差とカウンセリングを案内する |
| ナレッジにない質問 | 脱毛もできますか? / 明日空いてますか? | 脱毛はしていないと答える。空きは予約ページかLINEを案内する |
| 関係ない質問 | おすすめのラーメン屋は? | サロンに関する質問をお願いする |

うまくいった回答(特に表現ルール)はスクショを撮り、ポートフォリオに使う。

## 作業手順

目安は半日。公開は最後で、ナレッジを先に作る。

1. Google AI StudioでGeminiのAPIキーを作る
2. Difyの「設定」→「モデルプロバイダー」でGeminiにAPIキーを登録する
3. 「ナレッジ」→「ナレッジを作成」でesthe_faq.mdをアップロードする(高品質・ベクトル検索)
4. 「チャットボット」を新規作成し、モデルにGemini Flash-Liteを選ぶ
5. 手順欄に指示文を貼り、「コンテキスト」にナレッジをつなぐ
6. 開始メッセージとカテゴリボタン、フォローアップを設定する
7. プレビューで「初回の料金はいくら?」と聞き、5,500円と答えればナレッジ接続はOK
8. テスト計画の質問を試し、ナレッジか指示文を直す
9. 「公開する」を押し、URLをスマホでも開いて確認する

## 公開後の運用・改善

公開後はログを見て、答えられなかった質問をナレッジに足していく。

1. Difyの「ログ」で、「LINEからお気軽にお問い合わせください」と返した会話と👎がついた回答を探す
2. よく聞かれる質問ならesthe_faq.mdに項目を追加する
3. ナレッジにファイルをアップロードし直し、同じ質問で確認する

最初は自分や知り合いに試してもらい、ログを見る練習をする。将来は「月1回ログを見て更新する」保守サービスとして提案できる。その後、架空サロンのHPを作ってボットを埋め込む。
